## Verification completed

- Final full live regression: **897 passed, 2 skipped, 3 expected failures**,
  six existing NumPy overflow warnings, 124.72 seconds. New disposable database;
  PostgreSQL stopped after the run.
- Isolated PEP 517 build with setuptools 84.2.1 / build 1.6.1. Wheel built from
  the source distribution, not only directly from the checkout.
- `twine check --strict` passed for both final artifacts.
- Archive audit verified all **125 runtime/resource files** against source,
  including the 3.6 MB trained projection, conversation pack, both demo datasets,
  metadata, declared dependency fixes and all four entry points.
- A fresh Python 3.12.10 virtual environment, with system site packages disabled,
  installed the wheel and declared dependencies from public PyPI. `pip check`
  passed. After the CLI fix below, the final wheel replaced the initial candidate
  in that same clean dependency environment.
- All four installed console commands passed `--help` from outside the checkout
  source path, with offline assets and an intentionally invalid database DSN to
  ensure help does not require a connection.
- Installed module/version checks prove imports came from the clean environment's
  `site-packages`, not an editable checkout. The installed finance component
  preserved `4.500001x` against `4.500000x`.
- Installed `cpu-llm-demo healthcare` passed **12/12** and
  `cpu-llm-demo conversation` passed **12/12**, from a separate working directory,
  using a fresh PostgreSQL database and cached encoder assets. They do not depend
  on Git or repository example paths. PostgreSQL was stopped afterward.
- The release ZIP's embedded wheel/sdist hashes were verified against the same
  final artifact manifest.

The old ingestion CLI ignored `--help` and started model/database initialization.
The first candidate's installed command check exposed it. That attempt could not
connect to its default database; no ingestion was completed. The final candidate
parses help, unknown flags and conflicting selectors before construction, with
three dedicated safety regressions. Initial candidate artifacts/logs remain in
`build/release-1.10.0/first-build/` and the surrounding build folder; they must
not be uploaded. Only the files under `dist/1.10.0/` are final.

## Scope and remaining setup

Tested on Windows with Python 3.12; other supported Python/OS combinations were
not freshly executed for this release. The full suite uses the existing isolated
test environment; clean-install validation covers imports, command help, finance
precision and both actual demos, not the entire suite under every newly resolved
transitive dependency. Observed dependency versions are recorded in the manifest.
Optional NLP/coreference/decoder assets were not installed in the clean base
environment. External pretrained encoder downloads, PostgreSQL and model extras
are not embedded in this small wheel. Fictional demo success is not clinical
validation or universal answer accuracy.

Local evidence lives under `build/release-1.10.0/`: final build/archive/twine logs,
clean installation log and requirement snapshot, final full-suite log, installed
module check, four help logs, and installed demo responses/receipts. No PyPI
upload, account authentication, GitHub release or Git tag was performed.

See [the manual publishing command](1.10.0.md#maintainer-publishing-commands-manual-only).
