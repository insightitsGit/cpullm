# cpu-llm 1.11.0

Prepared November 3, 2026. Not uploaded by this build task.

This release adds evidence-backed reports/articles/design documents, explicit
prompt tone, verified technical sentence construction and executable manuals.
Tone is separated from KB search; the source does not need friendly wording.
Unsupported records remain quotations, missing sections stay missing and strict
documents remain quotation-only. No source-truth or clinical certification is implied.

## Consumer changes

- Document `reply.text` can contain verified derived prose when tone is requested.
  Original quotes/proofs and the canonical quotation view remain available.
- Single-fact style still publishes a companion. Inspect `stylistic.status`,
  verification, tone alignment, `document.presentation` and coverage.
- API style overrides prompt tone; strict settings disable generated tone.
- Document scans/continuation are bounded, caller-scoped and time-valid.
  General typed factual matching and arbitrary prose generation remain limited.

See the [user manual](../document-generation-user-guide.md) and
[findings specification](../document-generation-findings-spec.md).

## Build and verify

Use Python 3.11+ with setuptools 77+, build and twine:

```powershell
python -m build --outdir dist/1.11.0
python -m twine check --strict dist/1.11.0/cpu_llm-1.11.0-py3-none-any.whl dist/1.11.0/cpu_llm-1.11.0.tar.gz
```

The wheel includes the new runtime modules and existing trained projection/demo
resources. The sdist includes the user manual, root JSON specifications and
`examples/document_workflows/demo.py`. Historical raw response archives stay in
Git. PostgreSQL/pgvector and pretrained encoder assets remain separate setup;
the projection does not need retraining for demos. Optional parser models are
not bundled.

## Publish the verified files yourself

From `C:\code\cpullm`, after configuring your PyPI authentication:

```powershell
python -m twine upload dist/1.11.0/cpu_llm-1.11.0-py3-none-any.whl dist/1.11.0/cpu_llm-1.11.0.tar.gz
```

Pass the exact filenames, not `1.11.0`, a directory, or `dist/*` containing old
releases. Do not paste credentials into chat. After upload, verify in a new env:

```powershell
python -m pip install "cpu-llm==1.11.0"
python -m pip check
cpu-llm-demo --help
```

The artifact hashes and actual build/install checks are recorded separately in
`1.11.0-build-validation.md`. That validation record is not a clinical benchmark.
