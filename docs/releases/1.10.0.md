# cpu-llm 1.10.0 release

This release brings the pip distribution up to the current implementation.
Building these artifacts does not publish them. The maintainer will upload them
manually after review. Do not upload older files from the repository's `dist/`.

## Included

Strict evidence policy v3; default reviewed conversation pack; guarded mixed
greeting/factual routing; controlled tone companions; prompt interpretation,
batch/continuation handling and output layouts; finance ownership/precision
fixes; source permissions/history; trained projection and packaged corpora.

New installed commands:

- `cpu-llm-demo healthcare --out <new-dir>`: fictional label/record demo with
  12 expected-result checks, using packaged data and no Git dependency.
- `cpu-llm-demo conversation --out <new-dir>`: 12 social/factual routing examples.
- `cpu-llm-conversation-candidates --help`: local export review workflow.

The existing `cpu-llm-ingest` and `cpu-llm-serve` commands remain available.
Healthcare demo data are fictional; passing checks do not establish clinical
accuracy. External dialogue corpora, decoder checkpoints, spaCy models and
FastCoref/Coreferee model assets are not bundled. The pretrained retrieval
encoder still needs first-use download or a prepopulated cache. PostgreSQL with
pgvector must be configured separately. Optional features require their extras
and compatible assets; no single wheel bundles every third-party model.

## Response migration

The default small-talk node introduces `answer_status="conversation"` and
`response_kind="conversation"`. It has no document evidence or clinical audit.
Set `small_talk=False` / service `--no-small-talk` for an evidence-only contract.
Strict factual requests still bypass learned generation. Consumers should inspect
per-task outcomes, proofs and calculations rather than only nonempty reply text.
Tone output remains an opt-in companion in Python, not an automatic replacement
for the canonical reply. See the versioned specifications in `docs/`.

## Build and check

Use Python 3.11+ and a virtual environment. The build backend requires
setuptools 77+ for the SPDX project license metadata.

```powershell
python -m pip install --upgrade build twine
python -m build --outdir dist/1.10.0
python -m twine check --strict dist/1.10.0/cpu_llm-1.10.0.tar.gz dist/1.10.0/cpu_llm-1.10.0-py3-none-any.whl
Get-FileHash -Algorithm SHA256 dist/1.10.0/cpu_llm-1.10.0.tar.gz
Get-FileHash -Algorithm SHA256 dist/1.10.0/cpu_llm-1.10.0-py3-none-any.whl
```

PyPI uses `PYPI_README.md` as the long description so its documentation/sample
links resolve without repository-relative URLs. The wheel includes runtime code,
all declared package resources and installed demos. The source distribution also
includes examples, tools, tests discovered by setuptools and Markdown docs;
historical raw benchmark logs/response archives stay in Git rather than the wheel.

## Maintainer publishing commands (manual only)

From the repository root, after checking the exact artifacts and configuring
your own PyPI authentication locally:

```powershell
python -m twine upload --repository pypi dist/1.10.0/cpu_llm-1.10.0.tar.gz dist/1.10.0/cpu_llm-1.10.0-py3-none-any.whl
```

Use the explicit filenames; do not use `dist/*` because old 1.9.x artifacts may
also exist. Do not paste credentials into chat or commit them to the repository.
After upload, verify from a new environment:

```powershell
python -m pip install "cpu-llm==1.10.0"
python -m pip check
cpu-llm-demo --help
cpu-llm-conversation-candidates --help
```

Run the two demos after configuring the demo database and encoder cache. Review
the local artifact manifest and release validation report accompanying this build
before publication. This work does not create a PyPI upload, GitHub release or tag.
