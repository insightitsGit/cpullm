# Next package release assessment

Date checked: November 3, 2026.

PyPI's official JSON endpoint, `https://pypi.org/pypi/cpu-llm/json`, reported
latest version **1.10.0**. Both `pyproject.toml` and `cpu_llm.__version__` still
declare 1.10.0. Published 1.10.0 files were not rebuilt, replaced or uploaded.

## Decision

A new PyPI release is needed for pip users to receive the source-checkout
document/tone improvements. Recommended next version: **1.11.0** (proposed,
not yet built or published). This is a feature release rather than merely a
documentation patch.

The changes include a bounded document workflow for reports/articles/design
documents, explicit prompt tone separated from topic evidence, inverse-verified
technical sentence construction, source-quote fallbacks, section coverage,
formats/continuation, strict quotation-only reports, registered flag consumers,
manuals, runnable examples and regression cases. They do not train a general
language model or certify source truth.

## Migration points to publish

- Document replies can publish verified derived prose when tone is requested;
  original quotes/proofs and the canonical quotation view are retained.
- Single-fact tone still publishes a companion. Consumers must distinguish
  these publication contracts and inspect verification/status fields.
- API style overrides prompt tone; strict mode disables generated wording.
- Broader topic scans are bounded and authorized. Missing sections, unsupported
  constructions and remaining factual matcher limits stay explicit.

## Work before uploading 1.11.0

1. Bump `pyproject.toml` and `src/cpu_llm/__init__.py` together to 1.11.0; update
   package-facing README/release instructions without rewriting historical runs.
2. Build a new wheel and sdist in a distinct 1.11.0 output directory. Preserve
   the existing 1.10.0 files and their verification hashes.
3. Check distribution metadata and contents, including the new document/tone
   modules and the intended source-distribution manual/demo files.
4. Install the artifacts into a clean environment. Run dependency checks,
   installed CLI/help checks and database-backed prompt-tone/strict examples;
   record hashes and validation results for the exact built files.
5. Upload the exact wheel and tar.gz files when publication is requested.
   Do not pass a bare version string or a directory as a distribution filename.

This assessment accompanies the source commit. It is not a completed release
build, a PyPI upload, or evidence that `pip install cpu-llm` already supplies the
new behavior.
